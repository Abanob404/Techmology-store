# Technology Store — المرحلة الأولى: ترتيب المنتجات والعروض

تاريخ التحديث: 21 نوفمبر 2026

## الجديد الذي تم تنفيذه

- ترتيب ذكي افتراضي للكتالوج والعروض: **الأولوية اليدوية في الأدمن**، ثم الطلب الفعلي الذي تحوّل إلى فاتورة Technology POS، ثم التفاعل والقيمة التقريبية للمنتج، ثم خصم نشط وحداثة المنتج.
- تأخير الكابلات والوصلات منخفضة السعر في العرض العام تلقائيًا، **من دون** إخفائها من نتائج البحث المباشرة أو قسمها، مع إمكانية تفضيل أي منها من الأدمن.
- الحقول الجديدة لكل منتج: `merchPriority` من 0 إلى 100، و`merchTier`: `hero` (رئيسي)، `normal` (عادي)، `accessory` (مكمل). يتم حفظها عند إضافة/تعديل منتج.
- **إدارة ظهور المنتجات والعروض** داخل تبويب المنتجات: معاينة حسب القسم أو العروض النشطة، بحث، تعديل عدة منتجات، وحفظ تغييرات الأولوية بشكل مستقل عن مخزون POS.
- عدّاد مبيعات POS المؤكدة (آخر 90 يومًا بحسب تاريخ طلب الموقع) في معاينة الأدمن. *طلب الموقع قبل إنشاء فاتورة POS لا يُحسب بيعًا.* يتم تخزين نتيجة العد 5 دقائق لتخفيف الضغط على قاعدة البيانات.
- إخفاء شارات الخصم والسعر المشطوب للعروض منتهية المدة عند تحميل أو تحديث الصفحات، مع بقاء السعر الفعلي الحالي من قاعدة البيانات كما هو. **انتهاء مدة العرض لا يعيد السعر الأصلي تلقائيًا** لأن تسعير POS هو المصدر المعتمد ويحتاج تحديث السعر من المصدر أو الأدمن.
- تحسين تصنيف المنتجات ذات خيارات المخزون باستخدام إجمالي مخزون الخيارات عند ترتيب/عرض الكتالوج.
- رفع إصدار Service Worker لالتقاط ملفات JavaScript الجديدة.

## طريقة استخدام أدوات الإدارة

1. افتح لوحة التحكم ثم **المنتجات والمخزون**.
2. اضغط **فتح إدارة الظهور**.
3. استخدم البحث أو القسم أو اختيار **العروض النشطة فقط** لرؤية معاينة الترتيب.
4. عدّل الأولوية: `0` عادي؛ `50` أفضلية واضحة؛ `100` ظهور قوي جدًا، أو اختر **رئيسي** / **مكمل** وفعّل **مميز** عند الحاجة.
5. اضغط **حفظ ونشر التغييرات** ثم حدّث صفحة المتجر. الواجهة تحفظ المنتجات المعدلة فقط (بحد أقصى 100 في المرة الواحدة)، دون تغيير الأسعار أو المخزون.
6. في صفحات الأقسام، يظهر المنتج المطلوب عند البحث عنه أو زيارة قسمه، حتى لو كان من الإكسسوارات المكملة.

## طريقة النشر

- **اعمل نسخة احتياطية** من ملفات الموقع الحالي والإعدادات وقاعدة البيانات قبل النشر، وجرّب على Vercel Preview أولًا.
- استبدل ملفات المشروع الموجودة بالملفات داخل ZIP. لا تغيّر متغيرات البيئة أو التوكنات الموجودة في استضافتك.
- نفّذ أمر `npm run test:merch` من جذر المشروع (يتطلب Node.js 18+). لا يلزم تحديث أو تعديل قاعدة MongoDB يدويًا.
- انشر المشروع بنفس طريقة النشر المعتادة (Vercel/Git)، ثم اختبر صفحة المنتجات، إدارة الظهور، البحث عن وصلة، صفحة العروض، صفحة منتج، وتأكيد طلب اختباري **دون إنشاء فاتورة POS حقيقية**.
- قد يلزم تحديث الصفحة تحديثًا قويًا `Ctrl+Shift+R` لاستبدال الكاش في المتصفح بعد النشر.

## ملفات التنفيذ

- `merch-ranking.js`: دوال ترتيب مشتركة للعميل والأدمن؛ يمكن اختبارها بدون قاعدة بيانات.
- `merch-admin.js`: أداة الإدارة والمعاينة والحفظ.
- `app.js`, `index.html`, `products_page.html`, `sw.js`: عرض المتجر والتحديثات.
- `server/index.js`: الحقول الجديدة، API حفظ الأولوية المؤمّن بصلاحية `edit_product`، وإحصاء فواتير POS المؤكدة.
- `admin.js`, `admin.html`, `admin.css`: نماذج الإضافة/التعديل وشكل الأداة.
- `tests/merch-ranking.test.js`: اختبارات منطق الترتيب.

## حدود هذه المرحلة

- محرك الترتيب يعمل على المنتجات التي تعيدها حاليًا `/api/products` (الحد الحالي: 3000 منتج). النقل للبحث والفلترة من السيرفر وتحسين صفحات البيانات سيكون ضمن المرحلة الثانية/الخامسة.
- **هامش الربح الحقيقي لم يستخدم في ترتيب المتجر بعد**؛ استخدمنا سعر المنتج كمؤشر محدود للقيمة التجارية، مع تحكم أدمن يدوي قوي. بيانات تكلفة POS تظل سرية ولا تُرسل للمتصفح.
- الاختبارات المنفذة محليًا: فحص نحوي JavaScript واختبارات الوحدات. **لم يتم النشر على موقعك الفعلي أو إجراء اختبار قاعدة بيانات حي أو متصفح حي.**
