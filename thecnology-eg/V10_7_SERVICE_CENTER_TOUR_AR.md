# Technology Store V10.7 — مركز الصيانة + جولة شرح الموقع

## الجديد في الإصدار

### 1) مركز صيانة مستقل (بدون بيع بالجملة)
- `/maintenance` صفحة عامة لتقديم طلب صيانة الكمبيوتر واللابتوب والكاميرات والشبكات والتركيب والمشكلات الأخرى.
- نموذج طلب يتضمن الاسم، الهاتف، الخدمة، موديل الجهاز الاختياري، وصف المشكلة، المنطقة الاختيارية، وطريقة التواصل المفضلة.
- عند نجاح تسجيل الطلب يتم إنشاء رقم متابعة بصيغة `SRV-YYMMDD-XXXXXXXXXX` ويظهر فورًا للعميل. الطلب ليس حجزًا مؤكدًا للتكلفة أو الموعد.
- متابعة الحالة عبر رقم المتابعة ورقم الهاتف معًا. الاستعلام يستخدم `POST` ولا يضع رقم الهاتف في عنوان URL.
- مسار الأدمن **طلبات الصيانة** (يتطلب `manage_orders`): بحث، فلتر حالات، تحديث الحالة، ملاحظات الموظفين الخاصة، والتصفح بالصفحات. مؤشر للطلبات تحت المتابعة في الداشبورد.
- حالات الصيانة: جديد، تم التواصل، جاري الفحص، انتظار قطع غيار، جاري الصيانة، جاهز للاستلام، مكتمل، ملغي.
- كل وظائف الصيانة مستقلة تمامًا عن أسعار البيع، طلبات الموقع، فواتير POS، والمخزون.
- النسخ الاحتياطي اليدوي والسحابي أصبح يشمل `maintenance`. عند استعادة نسخة احتياطية أقدم لا تحتوي هذا المفتاح، يحتفظ النظام بطلبات الصيانة الحالية بدل حذفها.

### 2) الجولة التعريفية لأول زيارة
- نافذة تفاعلية حقيقية تشرح أماكن المنتجات والأقسام والبحث والفلاتر والسلة وخطوات إتمام الشراء.
- توضح أن العميل يراجع السلة ويدخل الاسم والهاتف والعنوان إذا كان الشحن متاحًا، وأن الموقع يسجل الطلب قبل متابعة التأكيد عبر واتساب؛ البيع النهائي يتم بفواتير Technology POS.
- الجولة تعرض مرة واحدة للمتصفح عند الزيارة الأولى للصفحات العامة، ويمكن تخطيها، وإعادة تشغيلها من زر **شرح الموقع** دائمًا.
- لا تنشئ طلبًا تجريبيًا، ولا تعدّل السلة أو بيانات المبيعات.
- تعمل على الموبايل والكمبيوتر، وتراعي خيار تقليل الحركة (reduced motion) وزر Escape، وتوفر زر السابق/التالي.

## الملفات الجديدة
- `maintenance.html` — صفحة مركز الصيانة.
- `maintenance.css` و`maintenance.js` — التصميم وتسجيل الطلب والمتابعة.
- `maintenance-admin.css` و`maintenance-admin.js` — واجهة الطلبات في الأدمن.
- `tour.css` و`tour.js` — الجولة التفاعلية.

## ملفات تم تعديلها
- `server/index.js` — موديل وحماية واجهات الصيانة، لوحة الأدمن، النسخ الاحتياطي.
- `vercel.json` — رابط `/maintenance`.
- `index.html`, `products_page.html`, `services.html` — روابط مركز الصيانة وتحميل الجولة.
- `admin.html` — تبويب جديد للأدمن.

## طريقة النشر الآمنة
1. احتفظ بنسخة احتياطية من المشروع وقاعدة البيانات الحالية قبل النشر.
2. ارفع نسخة V10.7 كاملة على فرع اختبار/Preview في Vercel أو ادمج ملفات تغييرات V10.7 في نسخة V10.6 الأساسية.
3. **احتفظ بمجلد `fonts/` الأصلي** لو كان موجودًا في بيئة النشر؛ الأرشيف المعاد تجميعه لا يوفر ملفات الخطوط الأصلية كاملة.
4. استخدم نفس متغيرات البيئة الحالية (`MONGODB_URI`, `JWT_SECRET`, Cloudinary وغيرها)، ولا تضف بيانات سرية للأرشيف.
5. لا يوجد أمر migration مطلوب مسبقًا؛ Mongoose ينشئ مجموعة `maintenancerequests` عند أول طلب مع اتصال MongoDB.
6. اختبر تقديم طلب صيانة حقيقي على بيئة اختبار، انسخ رقم المتابعة، وحدّث حالته من الأدمن بحساب لديه صلاحية `manage_orders`، ثم أعد استعلام المتابعة برقم الهاتف الصحيح.
7. جرّب الجولة على الكمبيوتر والموبايل وفي متصفح جديد، ثم التخطي وإعادة التشغيل.
8. تأكد من استمرار الطلبات المعتادة، والمخزون، وفواتير POS والتقارير بدون تغيير. بعد ذلك انشر على Production.

## واجهات API
| الوسيلة | المسار | الصلاحية |
|---|---|---|
| POST | `/api/maintenance/requests` | عام + حد طلبات وإدخال محقّق |
| POST | `/api/maintenance/track` | عام؛ رقم الطلب + هاتف مطابق |
| GET | `/api/admin/maintenance` | جلسة أدمن `manage_orders` |
| GET | `/api/admin/maintenance/summary` | جلسة أدمن `manage_orders` |
| PUT | `/api/admin/maintenance/:id` | جلسة أدمن `manage_orders` |

## نتائج الاختبارات وحدودها
- نجح فحص صياغة JavaScript للملفات الجديدة والخادم، وصحة JSON لـ Vercel.
- نجحت اختبارات ترتيب المنتجات السابقة: 7/7.
- نجح اختبار متصفح تلقائي لواجهة الصيانة: اختيار الخدمة، تسجيل طلب برد API تجريبي، ظهور رقم المتابعة، واسترجاع الحالة برد تجريبي، دون أخطاء JS.
- نجح اختبار الموبايل بدون تمرير أفقي، وتجربة الجولة (البدء، التالي، الإغلاق)، والجولة التلقائية والتخطي وإعادة التشغيل.
- **لم تُختبر عمليات قاعدة MongoDB الحقيقية أو صلاحيات الأدمن على قاعدة بيانات إنتاجية** في بيئة التنفيذ الحالية. يجب إجراء اختبار تكاملي على Vercel Preview قبل النشر العام.
- لا توجد رسائل واتساب آلية تُرسل عند تغيير الحالة؛ التواصل يتم يدويًا من خدمة العملاء حتى يتم ربط مزود رسائل بموافقة العملاء.
